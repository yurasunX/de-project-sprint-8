# Результаты проверки

Проверено 18 ноября 2026 года. Код проекта выполнен на настоящем Spark; запись в Kafka и PostgreSQL проверена сквозным запуском.

## Среда

- macOS arm64, Python 3.9.6, Java 17.0.20.1, PySpark 3.5.6.
- PostgreSQL 16.16: отдельный кластер проекта, только `127.0.0.1:15432`, SCRAM-аутентификация.
- Kafka: личные топики учебного окружения `infra.education-services.ru`, SASL_SSL / SCRAM-SHA-512, проверка сертификата включена. Уникальная consumer group с выданным префиксом.
- kcat 1.7.0, psycopg 3.2.13, PostgreSQL JDBC 42.7.5.
- Источник: собственная демонстрационная таблица `public.subscribers_restaurants`, три подписки для двух ресторанов. Источник и обратная связь находятся в одной собственной тестовой БД.

## Автоматические проверки

`python -m unittest discover -s tests -v` с подключённой PostgreSQL: **13 тестов, все пройдены**.

Проверены выбор подписчиков нужного ресторана, отсутствие подписчиков, временные границы `[start, end)`, будущие/завершённые акции, повреждённый JSON, обязательные поля, Unix seconds за пределами int32, состав Kafka JSON, кэширование при двух записях, освобождение кэша при ошибке, пустой батч и валидация конфигурации. Реальный PostgreSQL-тест подтвердил отсутствие повторной строки и сохранение `feedback='liked'` после повторной доставки.

## Сквозной запуск

Выполнено `scripts/e2e.py --env-file .local/project.env` на реальных сервисах:

1. kcat отправил активную, будущую и завершённую акции с новыми идентификаторами и существующим `restaurant_id`.
2. Spark прочитал сообщения из Kafka, загрузил подписки по JDBC и выполнил `foreachBatch`.
3. Для активной акции создано **2 сообщения в выходном Kafka-топике и 2 строки PostgreSQL**, по числу её подписчиков.
4. Будущая и завершённая акции дали **0 уведомлений** в обоих назначениях.
5. JSON содержит ровно 10 полей, без `feedback` и служебного `id`; начальный feedback в БД равен `NULL`.
6. Повторный запуск Spark с тем же checkpoint не изменил результат и не отправил уведомления повторно.

## Границы проверки

Сквозной запуск использовал режим `--once` (`AvailableNow`) настоящего Structured Streaming. Непрерывный режим с интервалом 30 секунд реализован, но отдельный длительный прогон не проводился. Атомарная доставка сразу в два назначения не гарантируется; ограничения at-least-once описаны в README.

Учебные Kafka и Jupyter-окружения созданы и доступны. В терминале выданного Jupyter обнаружены Python 3.8.13 и Spark 3.3.2 без доступной Java/kcat/PostgreSQL. На этом Jupyter проект не запускался; для проверки использован локальный Spark и личная учебная Kafka.

Dockerfile и Compose включены для воспроизведения стенда. Docker на машине отсутствует, поэтому сборка образа и запуск Compose не проверялись. Нагрузочные проверки и искусственный сетевой сбой между двумя живыми стоками не проводились; освобождение кэша при ошибке проверено тестом.

Секретные подключения, ключи, журналы, данные PostgreSQL и checkpoint находятся в `.local/` и не включаются в публикуемый комплект. Публикация на GitHub и отправка на ревью в Практикуме этим отчётом не подтверждаются.
